# MyNotes

在 VS Code 中管理 Markdown 笔记，并支持把笔记同步到 **Git 远程仓库** 或 **WebDAV 服务**。

笔记存放在你指定的任意目录中，与当前打开的工作区无关——无论在写什么项目，侧边栏里始终是同一份笔记。

## 功能

- 活动栏中的笔记树视图，支持多级文件夹
- 新建、重命名、删除笔记与文件夹（删除进回收站，可恢复）
- 跨全部笔记的快速检索
- 笔记目录发生变化时自动刷新
- 两种同步后端：Git 远程仓库、WebDAV
- 冲突时**保留双方内容**，绝不静默覆盖
- 独立的图形化设置页，改动即时生效，无需跳到 VS Code 全局设置页

## 快速开始

1. 打开活动栏中的 **MyNotes** 图标，点击「选择笔记目录」，指定一个用于存放笔记的目录。
2. 点击视图标题栏的 `+` 新建笔记。
3. 需要同步时，点击视图标题栏的齿轮图标打开设置页，选择同步方式并填好参数。

## 设置

点击视图标题栏的齿轮图标（或执行「MyNotes: 打开设置」）会打开一个独立页签，笔记与两种同步后端的全部常用配置都在这一页上，改一项立即生效。重复点击只会把已打开的页签带到前台，不会开出多个页签。

页面包含四节：**笔记**、**同步**（后端选择与触发时机）、**Git 仓库**、**WebDAV**。后两节跟随「同步方式」下拉框切换显示——选 Git 只显示 Git 一节，选 WebDAV 只显示 WebDAV 一节，选「不同步」则给出提示。切换方式不会清空另一种的配置，随时可以切回来继续用。

各后端一节内可直接完成：

- 录入/清除凭据（密码框，保存到系统密钥库，页面只显示「已保存/尚未保存」，不回显明文）
- **测试连接**：Git 用 `git ls-remote` 验证地址与令牌，WebDAV 发一次 PROPFIND，结果就地显示
本地仓库无需手动初始化：笔记目录还不是 Git 仓库时，首次同步会自动执行 `git init`、设置 origin 与分支、写入 `.gitignore`。

页面顶部的「在设置编辑器中打开」链接用于访问下表里未在表单中出现的原始配置项。

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `mynotes.notesLocation` | 空 | 笔记根目录的绝对路径，支持 `~` |
| `mynotes.defaultNoteExtension` | `md` | 新建笔记时自动补全的扩展名 |
| `mynotes.noteExtensions` | `["md","txt"]` | 树视图中显示的扩展名，填 `*` 显示全部文件 |
| `mynotes.sync.provider` | `none` | 同步后端：`none` / `git` / `webdav` |
| `mynotes.sync.onStartup` | `true` | 启动后自动同步一次 |
| `mynotes.sync.onWindowFocus` | `true` | 窗口重新聚焦时同步 |
| `mynotes.sync.focusCooldownSeconds` | `300` | 聚焦同步的冷却时间（秒） |
| `mynotes.sync.onSave` | `false` | 保存笔记后自动同步 |
| `mynotes.sync.onSaveDebounceSeconds` | `30` | 保存同步的防抖时长（秒） |
| `mynotes.sync.deviceName` | 空 | 设备名，用于提交信息与冲突文件命名，留空取主机名 |

> 同步的范围是笔记目录下的**全部文件**，而不只是 `noteExtensions` 里的扩展名——否则笔记引用的图片等附件会在其他设备上缺失。`.git`、`node_modules`、`.DS_Store` 等会自动跳过。

**密码与访问令牌不会写入设置文件**，而是保存在系统密钥库（VS Code SecretStorage）中，在设置页对应后端一节内录入（也可用命令「MyNotes: 设置同步凭据」）。凭据按「后端 + 地址」分别保存，换了仓库或服务器不会误用旧凭据。

### 跨 Profile 共享与跨设备同步

全部设置均声明为 VS Code 的 `application` 作用域：

- **同一台电脑的多个 Profile 间自动共享同一份配置**，不用在每个 Profile 里重复设置一遍。
- 若你开启了 VS Code 内置的 **Settings Sync**（登录 Microsoft / GitHub 账号后在左下角账户菜单启用），这些设置也会随之带到你的其他电脑上。

`notesLocation`（笔记目录路径）和 `sync.deviceName`（设备名）是例外：它们同样在本机各 Profile 间共享，但通过 `ignoreSync` 排除在 Settings Sync 之外。前者是本机文件系统路径，不同电脑的盘符和目录结构通常不同，同步过去大概率是个无效路径；后者本就该因设备而异，才能在冲突文件名和提交信息里区分是哪台设备的改动。设置页里这两个字段旁标注了「不跨设备」。

> 跨 Profile 共享和跨设备同步由两个独立机制控制：`scope` 决定前者，`ignoreSync` 决定后者。

**Settings Sync 不会同步凭据**——`mynotes.setCredential` 保存的令牌 / 密码走的是 SecretStorage，不在 Settings Sync 的同步范围内，换新电脑后仍需重新录入一次（但同一台电脑上的多个 Profile 已经共用同一份，不用重复录入）。

### 同时开着多个 VS Code 窗口

每个窗口都是独立的进程，都会各自跑同步。为避免两个窗口同时改写同一份基线（Git 后端还会直接撞上 `index.lock`），同步前会先在 `~/.mynotes/` 取一把**按笔记目录区分的进程锁**：

- 同一时刻只有一个窗口在同步，其余窗口跳过本轮；手动触发时会提示「另一个窗口正在同步」。
- 持锁期间会定期续期；窗口异常退出留下的锁超过 10 分钟后自动清理，不会永久卡住。
- 「上次同步时间」同样记录在共享目录中，窗口聚焦触发的冷却因此对所有窗口统一生效——否则每切换一次窗口都会触发一轮同步。
- 某条笔记正在窗口中编辑且尚未保存时，同步不会用远端内容覆盖它，而是把远端版本另存为冲突副本。

## Git 同步

需要本机已安装 `git` 并可在 PATH 中找到。

### 配置步骤

1. 先在 GitHub / GitLab / Gitea 等处创建一个仓库（**建议设为私有**）。
2. 打开设置页，「同步方式」选「Git 仓库」，在 Git 一节填入仓库地址与分支名。
3. HTTPS 地址在同一节录入访问令牌；点击「测试连接」确认能通即可，本地仓库会在首次同步时自动建好。

> **笔记目录不能放在其他 Git 仓库内部**，否则拒绝同步。哪怕笔记目录自己已经是一个仓库（嵌套仓库）也不行。
>
> 笔记仓库与你其他项目的仓库必须是彼此独立的两个仓库。判断依据是笔记目录在文件系统上的仓库归属，与远端地址用 SSH 还是 HTTPS 无关——两者都可以用任意协议，各自的凭据也分开保存。`.gitignore` 挡不住这件事：Git 判断归属看的是工作树，不是忽略规则。

### 认证方式

- **HTTPS + 访问令牌**：在托管平台生成一个个人访问令牌（PAT），按提示录入。
  - GitHub：Settings → Developer settings → Personal access tokens，勾选 `repo` 权限
  - 若服务端要求特定用户名，把地址写成 `https://用户名@host/仓库.git`，插件会从中取用
- **SSH**：地址填 `git@host:用户/仓库.git`，直接使用本机已配置的 SSH key，无需在插件中录入任何凭据。

令牌通过 `GIT_ASKPASS` 以环境变量传给 git 子进程，不会出现在命令行参数中（后者可被同机其他进程看到）。

### 同步流程

```
git add -A → 有改动则提交 → git fetch → git merge → 处理冲突 → git push
```

推送被拒（远端有新提交）时会自动重新拉取并重试一次。

## WebDAV 同步

适用于坚果云、Nextcloud、ownCloud、群晖等服务。

1. 打开设置页，「同步方式」选「WebDAV」。
2. 在 WebDAV 一节填入服务地址、用户名、远端路径，录入密码。
3. 点击「测试连接」确认能通。

**坚果云**：地址为 `https://dav.jianguoyun.com/dav/`，密码必须使用「应用密码」（账户信息 → 安全选项 → 添加应用），不能用登录密码。

### 同步策略

WebDAV 本身没有版本概念，插件通过一份**本地状态清单**记录上次同步完成时各文件的指纹，再用「上次同步态 / 本地当前态 / 远端当前态」三方对比来判断每个文件发生了什么。

这样才能区分「本地新增」和「远端已删除」——只比较修改时间是做不到的，会把已删除的笔记反复复活。

清单保存在用户主目录下的 `~/.mynotes/` 中，不会出现在笔记目录里，也不会被 Git 后端一并同步；每台设备各自维护自己的清单。

它**不放在插件的 globalStorage 里**，因为那个路径随 Profile 变化——换一个 Profile 就等于基线丢失，退化成首次同步后，此前在本机删除、而远端仍保留的笔记会被重新下载回来。放在主目录下，同一台电脑的各个 Profile、各个窗口共用同一份基线。从旧版本升级时，原先存放在 globalStorage 中的清单会在首次同步时自动迁移过来。

清单不存在（真正的首次同步）会保留双方全部内容，不会误删；清单**损坏**则会明确弹窗提示，因为此时同样会退化为首次同步，已删除的笔记可能重新出现。

## 冲突处理

两个后端使用同一套策略：**任何情况下都不丢内容**。

| 情况 | 处理方式 |
| --- | --- |
| 本地与远端都修改了同一篇笔记 | 本地版本原地保留，远端版本另存为 `原名.conflict-设备名-时间.md` |
| 远端已删除，但本地有修改 | 保留本地版本并重新上传 |
| 本地已删除，但远端有修改 | 恢复远端版本 |

冲突发生时会弹窗提示，可直接打开冲突副本对照。副本本身也是一篇普通笔记，会同步到其他设备，因此两边都能看到这次冲突。合并完成后自行删除副本即可。

## 命令

全部命令可在命令面板中以 `MyNotes` 前缀找到：

| 命令 | 说明 |
| --- | --- |
| 选择笔记目录 | 设置笔记根目录 |
| 新建笔记 / 新建文件夹 | 在根目录下创建 |
| 检索笔记 | 跨全部笔记按名称快速跳转 |
| 刷新笔记列表 | 手动刷新树视图 |
| 立即同步 | 手动触发一次同步 |
| 打开设置 | 打开设置页（笔记、同步、Git/WebDAV 参数） |
| 设置同步凭据 / 清除同步凭据 | 管理当前启用后端的密码与访问令牌 |
| 查看同步日志 | 打开输出面板中的日志 |

插件不预置快捷键，以免占用你已有的按键。需要的话可在「键盘快捷方式」中自行绑定。

## 开发

```bash
npm install
npm run watch                # esbuild 监听构建
npm test                     # 单元测试
npm run check-types
npm run lint
npm run verify:git           # 用真实 git 仓库验证同步与冲突处理
npm run verify:activation    # 用 vscode 桩件验证激活流程与命令注册
npm run package              # 产出 .vsix
```

在 VS Code 中按 <kbd>F5</kbd> 启动扩展开发宿主进行调试。首次按下会自动：

1. 运行 `scripts/setup-debug-workspace.mjs`，在 `.dev/test-workspace/notes` 下生成一份示例笔记（不受版本控制），并把该目录写入 `.dev/test-workspace/.vscode/settings.json` 的 `mynotes.notesLocation`
2. 启动 esbuild 监听构建
3. 用独立的 `--user-data-dir`（`.dev/user-data`）打开这个示例工作区，调试宿主的设置、状态与你日常使用的 VS Code 完全隔离

调试宿主启动后即可直接在笔记树里看到示例内容，无需手动执行「选择笔记目录」。示例笔记的编辑会保留到下次调试；如需清空重来，运行 `npm run debug:reset`。

`verify:git` 会在临时目录建立一个裸仓库和两个克隆，模拟两台设备走完「双方修改」「一方删除一方修改」「新增/新增」「无关历史合并」等场景，验证冲突处理不丢内容。

> `watch` 任务的问题匹配器直接写在 `.vscode/tasks.json` 里（识别 `esbuild.mjs` 打印的 `[watch] build started` / `[watch] build finished`），不依赖任何第三方扩展，装好依赖后开箱即用。
